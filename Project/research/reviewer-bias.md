# LLM reviewer/critique loop design (researched 29 Aug 2026)

- "Mind the Blind Spots" (https://arxiv.org/html/2502.17086v4): LLM reviews
  systematically over-attend technical validity, under-attend broader
  judgment — the exact failure our audit loop showed (fraud-checked
  everything, never questioned direction).
- Same-base-model review panels are structured SELF-critique, not
  independent verification; unanimous agreement can be shared bias
  (agent-review-panel README's own limitation note,
  https://github.com/wan-huiyan/agent-review-panel). Our Claude-optimizer /
  GPT-judge split is cross-family — preserve it.
- Reviewer prompt-injection is a live attack class (ICML 2025 hidden-prompt
  scandal; https://arxiv.org/pdf/2512.10449) — keep neutral runner-generated
  packets; never let the optimizer author reviewer inputs free-form.
- Sycophancy measurement is methodologically messy
  (https://openreview.net/forum?id=v5Akllkc8i) — design AGAINST agreeable
  defaults: verdict-forced formats (APPROVE/REVISE/REJECT), explicit
  "a wrong looks-good costs the competition" stakes, owner-voiced prompts
  with no authorship signals.

## Design rules extracted for harness v2
1. Two reviewer tracks: integrity (per champion) + STRATEGY (checkpointed,
   different prompt, max effort).
2. Cross-model-family always; blind, neutral evidence.
3. Forced-verdict schemas; enumerate-required-revisions on REVISE.
4. Reviewer inputs generated by the frozen tooling, not the optimizer.
